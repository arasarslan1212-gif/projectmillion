# Decisions

Where the spec was ambiguous, or reality forced a choice, the option most honest to the end user wins. Each entry records the choice, the reason, and what it affects.

---

### D-001: Synthetic fixtures while the network is blocked
**Context.** Egress to every data provider is blocked in the build environment, so the 6 real tickers can't be recorded.
**Decision.** Ship two fixture sets that go through the same record/replay HTTP layer and the same adapters:
- `fixtures/recorded/`: real responses, produced by `make record-fixtures` (AAPL, JPM, O, an unprofitable growth name, a high-dividend utility, a sparse small cap).
- `fixtures/synthetic/`: generated by `scripts/make_synthetic_fixtures.py` for fake tickers `ZZTEC, ZZBNK, ZZREI, ZZGRO, ZZUTL, ZZSML` plus a synthetic peer universe.

Synthetic companies are named "… (Synthetic)". Every page that shows them carries a persistent **SYNTHETIC TEST DATA: NOT A REAL COMPANY** banner, and charts carry a watermark. The flag is `companies.is_synthetic`, set from fixture metadata and never inferred.
**Why.** "Never invent data" is about misleading users. Clearly labeled synthetic fixtures with non-existent tickers can't be mistaken for real data, and they let every code path be tested now.

### D-002: The 12-month target is not intrinsic value
The engine estimates intrinsic value V with each method. The **long-term intrinsic value** is V. The **12-month P50** is `P0 · (1 + k_e − dividend_yield) · exp(λ · ln(V/P0))`, with λ = `valuation.convergence_12m` (default 0.4).
**Why.** Assuming full convergence in 12 months is not supported by evidence and produces over-confident targets. λ is visible on the Methodology page, and the backtest measures whether it's miscalibrated.

### D-003: The price range is an honest 80% interval
P10/P90 come from a log-normal with σ² = σ_mkt² + (λ·σ_val)², multiplied by a widening factor `1 + w·(1 − confidence/100)`. σ_mkt is the 1-year realized volatility (implied volatility when available). σ_val is the log-dispersion of the Monte Carlo intrinsic values combined with the dispersion between methods.

### D-004: Charts use ECharts, not Recharts
Radar, heatmap, tornado, histogram with reference lines and bubble scatter are all first-class in ECharts. Recharts has no heatmap. Price charts use TradingView Lightweight Charts, with the attribution logo on and a NOTICE credit on the About page.

### D-005: Without an LLM key, templates are used and sentiment is not estimated
With no `ANTHROPIC_API_KEY`, every narrative uses deterministic templates built from the facts JSON; these always pass the validator. News sentiment is **not** estimated with a crude word list. It is shown as "not computed (LLM not configured)", and the Sentiment pillar is reweighted away, with the missing input listed.

### D-006: Analyst data tiers and labels
`pro` = Benzinga via Massive (per-analyst). `starter` = FMP `price-target-news` (per-analyst targets) joined to FMP grades for ratings (same firm, ±3 days). `free` = Finnhub recommendation trends (consensus distribution only). The UI states which level applies: "Per-analyst track records", "Firm-level track records only", or "Consensus only".

### D-007: Benchmarks
The S&P 500 is proxied by **SPY** (adjusted close, so total return). Sectors use the SPDR Select Sector ETFs (XLK, XLF, XLE, XLV, XLI, XLY, XLP, XLU, XLRE, XLB, XLC). The proxy is labeled wherever it's used.

### D-008: Stock-based compensation
SBC is treated as a real expense. GAAP operating income already deducts it, so FCFF built from NOPAT never adds SBC back. "FCF" shown in quality metrics is CFO − capex, alongside "FCF after SBC" (CFO − capex − SBC).

### D-009: Stale analyst targets
Targets older than `analysts.stale_months` (default 6) are greyed out and excluded from both consensus figures. This matches the spec's default.

### D-010: Meaning of the Trust Rating
The Trust Rating measures business strength, reliability and valuation *relative to sector*. It is **not** a buy/sell recommendation and is never phrased as one. Grade bands: A+ ≥ 90, A ≥ 85, A− ≥ 80, B+ ≥ 75, B ≥ 70, B− ≥ 65, C+ ≥ 60, C ≥ 55, C− ≥ 50, D ≥ 40, F < 40.

### D-011: Docker isn't testable in the build environment
Compose files are provided, but the Docker daemon isn't available here. Local verification uses SQLite and a local PostgreSQL 16 instance for migrations.

### D-012: PDF export
PDF export uses a dedicated print stylesheet plus the browser's print-to-PDF. This needs no server dependency, and what you see is what you get. Server-side rendering with Playwright is on the ROADMAP.

### D-013: The synthetic set is generated in-process, and fixture sets never mix
The synthetic "fixtures" are served by an in-process HTTP transport (`engine/synthetic/server.py`), not stored as files. It speaks each provider's documented response shape, so the real adapters parse it exactly as they would parse live data. It is deterministic (seeded), which keeps the repository small and stops synthetic fixtures from going stale. Mock mode uses exactly one set (`FIXTURE_SET`: `recorded` | `synthetic` | `auto`). Synthetic companies can therefore never be ranked against real ones, and real benchmark tickers (SPY, XLK, …) are never given synthetic prices: the synthetic set uses its own benchmarks (`ZZMKT`, `ZZSTK`, …).

### D-014: Chart palette
Charts use the validated reference palette from the data-viz method (fixed categorical order, reserved status colors, one-hue sequential, blue↔red diverging with a gray midpoint), defined once as CSS tokens in `apps/web/app/globals.css` for light and dark themes. Muted text is darkened to `#6b6a65`, so small text meets WCAG AA (4.5:1) on the light surface.

### D-015: Name
Working name "Candor" (fits the honesty-first product). Rename it in `apps/web/lib/legal.ts`.

### D-016: Every indicator is computed in the engine
SMA/EMA/Bollinger/RSI/MACD are computed in Python and sent with the chart data, so the browser only draws. The price chart's "% compare" mode uses the chart library's percentage scale, which rebases each displayed series to its first visible value. That is display scaling, not a new figure.

### D-017: Sector percentiles compare trailing-twelve-month values with industry calendar-year values
The Trust Rating scores the company's latest trailing-twelve-month ratios against the industry distribution from the latest complete calendar year of SEC frames. This mixes periods by up to a year, but keeps the rating responsive to recent quarters; comparing the company's own stale calendar-year value would hide them. The peer table (M2) uses the same calendar-year basis for every row, so it stays strictly comparable. Both notes appear in the UI.

### D-018: Composite accounting scores use published thresholds, not percentiles
Altman Z, Piotroski F and Beneish M are scored against anchors derived from their published thresholds, because those thresholds carry the meaning. The right Altman variant is chosen automatically: the original Z for manufacturers (SIC 2000–3999), Z'' for other non-financial companies, and none for banks, insurers and REITs.

### D-019: Red flags cap pillars and deduct points, with a cap on the total deduction
A triggered red flag caps its pillar (e.g. going-concern language caps Financial health at 20) and deducts a documented number of points from the overall rating. Total deductions are capped at 20 points, so the pillar evidence still dominates. Every check lists whether it fired, passed or could not run, so "no flags" is never confused with "not checked".

### D-020: Peer sets are widened to a minimum size
Peers must be in the same SIC industry and, by preference, within 10× the company's revenue. For the largest or smallest company in an industry, that band can leave only two or three peers, which makes the peer medians and the P/B–ROE regression unreliable. When fewer than `peers.min_peers` (8) filers fall inside the band, the nearest-sized same-industry filers outside it are added, and the selection note says so. You can still edit the peer set.

### D-021: Today's price is the actual close; returns use adjusted closes
Valuation compares per-share values with the last actual (split-adjusted, not dividend-adjusted) close. Dividend-adjusted closes are used only for returns (beta, volatility, drawdowns). In point-in-time mode this avoids a subtle look-ahead: back-adjusting an old price for dividends paid later would lower the historical price level using information that did not exist yet.

### D-022: Monte Carlo and path simulations are seeded per ticker and date
Every simulation uses a seed derived from the ticker, the as-of date and the configured base seed. The same report is exactly reproducible, while different tickers do not share random draws. The drawdown probability simulates daily steps, which slightly understates the continuous-time probability (a missed intraday low). The closed-form continuous-time value for the driftless case is checked in the tests.

### D-023: What counts as an analyst "call", and how feeds are joined
A call is one analyst (or firm) publishing a target and/or rating on a date. FMP's per-analyst targets carry no rating and its firm grades carry no analyst, so a target takes the rating of a grade from the same firm within ±3 days (firm names compared without punctuation). A grade with no matching target stays a firm-level call (rating only). A rating stays in effect until changed, for up to 12 months, so a later target-only note inherits it ("carried"). A call with no rating gets its direction from the target: at least 10% above the price counts as Buy-equivalent, at least 10% below as Sell-equivalent. Published targets are in the share units of their date and are split-adjusted with the split history, never with a provider's pre-adjusted field.

### D-024: Scoring a call
A call is scored from the close on its publication date, the first price a reader could act on. Horizons are 63, 126 and 252 trading days, and a horizon counts only once it has fully passed by the report date. "Target reached" uses closing prices: a close at or above a bullish target (at or below a bearish one) within 252 trading days. The error at the horizon is |price after 12 months ÷ target − 1|. Directional skill is the call's direction × (the stock's total return − the benchmark's total return), against both the market and the sector fund; Holds are not directional. This follows the spec's definition, so in a stretch where the covered stocks beat the market, persistent Buy ratings earn some credit. The bias measure (target-implied return − realized return) partly offsets that.

### D-025: Trust Scores use recency weights and hierarchical shrinkage
Metrics are recency-weighted means (half-life 3 years). Each metric is shrunk toward a prior worth 15 calls: the analyst's record on this stock toward their sector record, that toward their record on all stocks, and that toward the average analyst. The score maps the shrunk metrics to 0–100 with configured anchors and weights (hit rate 30%, error 25%, directional 35%, bias 10%). Consecutive calls on one stock overlap in time, so the effective sample is smaller than the count; the fairly strong prior partly compensates, and the section says so. Herding (the share of the gap to other analysts' consensus that a revision closes) is shown but not scored, since following the consensus is not in itself wrong.

### D-026: Consensus rules
The all-analyst consensus is the plain mean of each analyst's latest target from the last 6 months. The trusted consensus weights the same targets by (Trust Score ÷ 100)²; analysts without a scored record get the average analyst's score, so they are neither ignored nor favoured. A target more than 3× above or below the median active target is treated as a likely data error (for example an unadjusted split), flagged in the table and excluded from both figures. The app's valuation uses the trusted consensus as its analyst input.

### D-027: Analysts' cross-stock history comes from the app's own database
No affordable feed returns an analyst's entire history in one call. Every report ingests the subject and its peers (sector analysts overlap heavily), and a nightly job (`score_analysts`) ingests the configured universe (S&P 500 members by default) and stores all-stock scores. The section states how many stocks and scored calls the scores rest on. On the free tier there are no analyst-level records: the section falls back to rating counts and the provider's plain consensus, and says so.

### D-028: Broker cards describe the call, not the research
The data feeds carry a headline and link, not the firm's reasoning. Each card's summary is generated by the app from the structured fields (the rating change and the target change). It says explicitly that the reasoning is not in the feed and links to the public headline. Research text is never reproduced or paraphrased.

### D-029: EPS revision history is built from the app's own daily snapshots
The configured providers return only current estimates, not their history. The app stores one consensus snapshot per day, so the EPS revision chart starts on the first snapshot and says so. The target-revision chart needs no snapshots: it is rebuilt from the dated analyst calls, point-in-time for each month end.

### D-030: The synthetic analysts carry hidden skill, bias, noise and herding
Each synthetic analyst has known skill, optimism bias, noise and herding parameters, so the scoring can be tested against ground truth. The tests check that measured optimism ranks true bias, that scores fall with bias and rise with skill, and that in a controlled simulation an accurate analyst clearly outscores a noisy one on the same stock. Analyst behaviour uses its own random stream, so tuning it never changes the rest of the synthetic market. Published targets stay within 0.5×–3× the price.
